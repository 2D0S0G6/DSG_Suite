## Feature Breakdown

### 🔓 IDOR Scanner

```
INPUT:  URL with sequential IDs
        /api/student?roll=20230001

PROCESS:
  1. Extract numeric parameter (roll=20230001)
  2. Generate mutations:
     - Increment: 20230002
     - Decrement: 20230000
     - Double: 40460002
     - Special: 0, -1, 9999
  3. Test each mutation
  4. Compare responses
  
OUTPUT: If different student data returned
        → IDOR VULNERABILITY FOUND
```

### 🚫 Authorization Scanner

```
INPUT:  All discovered endpoints

PROCESS:
  1. Categorize by patterns:
     - /admin/* → Admin
     - /teacher/* → Teacher
     - /api/user/* → Student
  2. Test unauthenticated access
  3. Test cross-role access
  4. Test method overrides (GET vs POST)
  
OUTPUT: Endpoints accessible without permission
        → AUTHORIZATION BYPASS FOUND
```

### ⚙️ Parameter Mutator

```
INPUT:  Endpoint with parameters
        /api/grades?student_id=123&exam=5

PROCESS:
  1. Extract parameters
  2. Generate mutations:
     - student_id: [124, 122, 246, 62, -123, 0, 9999]
     - exam: [5, 4, 6, ...]
  3. Test removed params
  4. Test type confusion
  5. Compare impacts
  
OUTPUT: Parameter logic flaws
        → EXPLOITATION POSSIBLE
```

### 🔍 Response Analyzer

```
INPUT:  HTTP response from server

PROCESS:
  1. Compare multiple responses
  2. Look for:
     - Stack traces
     - Database errors
     - API keys/secrets
     - File paths
     - Different content sizes
  3. Test timing (timing attacks)
  4. Test auth bypass patterns
  
OUTPUT: Information leakage
        → SECRETS EXPOSED
```

### ❌ Old Thinking (v1.0)
```
"Can I inject <script>alert(1)</script>?"

"Are security headers present?"

Testing: Payload-centric
→ XSS, SQLi, CSRF
→ Catches obvious injection points
→ Misses authorization logic
```

```

→ IDOR, Authorization, Parameters
→ Catches real-world attacks
→ Finds the bugs that matter
```
